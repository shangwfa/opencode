# RAG 检索质量评估准则（evaluation rubric）

> 本准则是 U/V/W 三系列用户场景测试与 L3 判官实践中沉淀的**标准评估规则**，作为后续检索质量回归与评估的规范依据。
> 方法论：期望先行（先锚定原文再跑，杜绝倒推）· 双判定交叉（确定性断言 + LLM 判官）· 证据落盘可复现 · 诚实边界声明。

## 1. 体系总览：四层判定

| 层 | 判什么 | 手段 | 可靠性 |
|---|---|---|---|
| **L1 机制层** | 隔离、契约、只读、来源一致 | 确定性断言（脚本） | 完全可靠 |
| **L2 召回层** | 目标文档命中 + 关键事实可见 | 确定性断言（脚本） | 可靠（保守下界）|
| **L3 可答层** | 仅凭前 K 条片段能否回答用户问题 | LLM 判官（saas 会话） | 初测方向性，**必须校准后使用** |
| **L4 无害层** | 跨库泄漏、编造、过期内容（负向断言） | 确定性断言 | 完全可靠 |

## 2. L1/L2 确定性断言（硬底线）

每问 × semantic/hybrid 双模式执行：

1. **契约**：HTTP 200、`success=true`、`results` 为数组且 ≤ topK
2. **隔离**：每条结果 `documentId` ∈ 目标知识库（PG 预查集合）；文档列表同理（跨库泄漏零容忍）
3. **目标命中（hit@K）**：前 K 条（默认 5）包含预先锚定的目标文档
4. **事实可见（fact-coverage@K）**：命中片段归一化（去空白/`*`/反引号、小写）后包含预设事实**原文子串**
5. **来源一致**：`docUrl`/`docName` 与文档详情接口 metadata 完全一致
6. **只读一致**：documents 与向量表整表 md5 快照前后一致
7. **期望先行**：跑之前先对详情原文断言"事实确实存在"，不存在即 BLOCKED（不算通过也不算失败）

**语义**：L2 通过 ⇒ 可回答（实测交叉验证 L2✓L3✗ = 0），因此 L2 作回归守门员——红了即真退化。L2 失败 ≠ 用户拿不到答案（存在等价证据与跨片段拼接，需 L3 甄别）。

## 3. L3 判官协议

- **判官载体**：opencode saas 会话（`POST /api/session` + `prompt_stream` SSE；Basic auth；模型经会话参数指定）
- **判定标准（prompt 要点）**：`can_answer=true`＝片段中可见核心信息（关键结论/步骤/数字/限制，不要求措辞完美）；`false`＝列 missing；**只依据片段，不得用自身知识补全**；禁止调用工具
- **批量**：6~7 项/批 list-wise；输出严格 JSON（`[{"id","can_answer","missing","used"}]`）；批结果落盘、断点续跑
- **回复提取**：`GET /api/session/:id/message?order=asc` 取最后一条 `type==='assistant'` 的 `content[].text`

### 3.1 判官可靠性三步校准（强制，未校准的 L3 结果只能标注"初测"）

文献依据：LLM-as-judge 存在系统性 position bias（list-wise 高危）、verbosity bias、跨运行不一致（ACL 2025 系统研究等）。

1. **重复稳定性**：同输入、**新会话**（避免上下文记忆）原序重判 → `repetition stability = 与首轮一致比例`；建议 ≥ 85% 才可用。**实测（2026-10-13，20 项样本）：95%**
2. **顺序敏感性**：片段乱序（固定 seed 可复现）重判 → `order stability`。**实测：100%（无 position bias 迹象）**——合理：本协议为逐项独立判定（非 pairwise 比较），而文献的 position bias 主要发生在比较场景；仍需在判官/prompt 变更时复测
3. **分歧抽检**：对 L2✗L3✓ 分歧项逐条人工核对（清单自动生成：问题 + L2 失败原因 + 预设事实 + 5 片段摘要），分类为「等价证据/拼接可答（判官对）」或「偏宽（判官错）」；偏宽率用于修正 can-answer 率。**预标注（AI 自标，待人工复核）：13 项中 8 项合理（等价证据/拼接）、5 项偏宽（U10×2、U12、W05×2——核心事实确不可见），偏宽率 ≈ 38%，修正后 can-answer@5 ≈ 75%**

## 4. 指标定义与当前基线（2026-10-13，kb_yingdao_harness_zh_cn，39 问）

| 指标 | 定义 | 当前值 | 备注 |
|---|---|---|---|
| hit@5（L2） | 目标文档进前五比例 | 64.6% | 确定性；保守下界 |
| fact-coverage@5 | 预设事实在前五可见 | 随 L2 | 确定性 |
| **MRR** | 目标文档首个命中排位倒数的均值 | **0.666** | 确定性；hybrid 三系列全面 ≥ semantic（U .669/.542、V .903/.771、W .561/.552）|
| can-answer@5（L3） | 判官认定"片段可回答"比例 | 81%（初测）| 判官稳定（重复 95%/乱序 100%）但偏宽：抽检预标注偏宽率 5/13≈38%，**修正后 ≈ 75%** |
| source-correctness | 来源字段一致率 | 100% | 确定性 |
| 真失败率 | L2✗ 且 L3✗ | 19% | 需 Agent 层对策 |

### 4.1 统计效力声明（必须随指标一起展示）

- 独立样本 = 问题数（双模式高度相关），不是判定项数；39 问下比例的 95%CI 约 ±15pp
- **禁止**基于 L3 做系列间精细对比（差异在噪声内）；L2 差异对固定问题集是确定性事实，可对比
- 问句由 AI 生成（非真实用户日志），难度分布未标定——指标代表"这套问题集上的表现"，泛化需真实 query

## 5. 已知边界

1. 判官判断"片段可回答性"，**不是**最终 Agent 答案质量（faithfulness/引用准确/拒答未覆盖，属生成层评估）
2. 数据泄漏无法排除：公开文档可能进入判官模型预训练语料，"不用自身知识"仅是 prompt 约束
3. 与 RAGAS 对照的缺口：**Context Precision**（前五中相关片段占比/噪声比例）未测——判官可顺带输出每片段相关性补齐；Noise Sensitivity、Faithfulness 未覆盖
4. "单一目标文档"断言存在等价证据误伤（实测占 L2 失败 46%）；升级方向：目标文档集合

## 6. 复现步骤

```bash
# 前置：知识服务(18787，inner embedding) + saas(14096) + PG(knowledge-pg) 运行中
# ① 三系列检索（各自 md 内嵌脚本，证据落盘 evidence.json）
# ② 判官：rag-judge/run-judge.mjs（批量判定 → verdicts.json）
# ③ MRR+分歧清单：rag-judge/mrr-and-review.mjs（→ mrr.json + disagreement-review.md）
# ④ 稳定性：rag-judge/stability.mjs（原序重判 + 乱序重判 → stability-*.json）
# ⑤ 人工抽检 disagreement-review.md，回填偏宽率
```

## 7. 变更规则

- 修改检索行为（召回/融合/重排/阈值）后：重跑三系列 L1/L2 + 判官，对照第 4 节基线；L2 红必须归因后才能合入
- 新增问题集时遵循"读者角色造问"方法论（见 [full-coverage.md](./full-coverage.md)），并保持期望先行
- 判官模型/prompt 变更：必须重跑 3.1 三步校准
