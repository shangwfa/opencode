# Graph 固定 E2E 用例

## 范围与判定

本组用例以固定 extraction fixture 写入 PostgreSQL，再从数据库读取并断言图状态或检索结果。它验证图构建、存储和消费之间的协作，不验证 LLM 抽取质量。用例编号对应 `src/graph/e2e/graph-acceptance.test.ts` 中同名 P0 描述。

| 编号 | 前置与执行 | 预期结果（确定性断言） | 过程/数据验证 |
|---|---|---|---|
| G-P0-1 基础建图 | 将后端服务 fixture 逐份写入同一知识库 | 节点类型与名称集合符合 fixture；图有 4 条边 | 调用关系从订单服务指向库存服务；边来源文档为订单服务文档 |
| G-P0-2 重复导入幂等 | 同一 fixture、同一文档连续导入两次 | 仍为 3 个节点、2 条边 | 订单服务节点 frequency 至少为 2 |
| G-P0-3 关系检索去噪 | 导入 fixture 后按关系“调用”和主体“订单服务”查询 | 恰好返回一条三元组 | 主体、关系、目标分别为订单服务、调用、库存服务 |
| G-P0-4 文档删除 | 导入 fixture 后删除 `doc-order-service` | 删除订单服务及订单数据库，保留库存服务及库存数据库 | 被删文档的节点-文档关联为空 |
| G-P0-5 事实冲突 | 导入含部署位置冲突的固定 fixture，并按“部署于”解析 | 旧断言被 superseded，活动断言只剩一条 | 活动目标为生产集群 B，且来源文档 id 正确 |

## 扩展全链路场景

以下场景由 [`graph.e2e.test.ts`](../../../src/graph/e2e/graph.e2e.test.ts) 自动化，作为更广的回归覆盖：

1. 两份文档共享实体后，图补全可跨文档检索关联。
2. 异写实体合并后边迁移，重复节点消失。
3. 新旧时间事实冲突后，时间检索隐藏旧事实。
4. 按文档删除后清理独占节点与关联，同时保留仍被引用的图数据。
5. ontology 校验过滤违规实体类型和关系。
6. 从源文件抽取代码图，验证依赖查询和反向影响查询。
7. 节点集合圈选子图，并验证边类型统计。
8. 同一图输出可视化数据及 Turtle/N-Triples RDF。
9. 矛盾检测产生可追溯的 contradicts 结果。

## 通过与失败处理

- G-P0-1~5 全部通过，才满足固定核心图语义验收；扩展用例的通过情况单独报告。
- 执行前确认 `DATABASE_URL` 指向专用测试数据库。自动化测试使用 `test_graph_acceptance` schema；不要指向生产 schema。
- 报告 PASS/FAIL/SKIP 数量及失败用例。环境未就绪导致的 skip 是阻塞，不是 PASS。
- 若失败，保留 Bun 输出和对应 PG 测试数据证据；先判断是环境阻塞还是断言不符，再改动实现并重跑同一命令。
