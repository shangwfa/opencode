# GraphRAG 全链路验收

> 本文件定义完整验收范围，不代表所有条目已自动化或已通过。现有依据、缺口和运行阻塞见 [覆盖审计](./coverage-audit.md)。旧的局部 PASS 不能替代本文件的全链路门禁。

## 1. 范围与入口

主链路：**源文档 → 转换/分块 → 抽取 → 合并/本体校验 → PG 图、RDF 与溯源 → 图检索 → 可见证据 → SaaS Session graph agent → 最终回答/引用 → 更新/删除 → 再检索**。

扩展输入与消费：OpenAPI/Swagger、代码、事件、会话蒸馏、结构化行、全局上下文、真值/反馈、检索 trace、语义布局和 RDF 导出。结构化行有独立 RowStore/RowRetriever/自然语言查询组件，**不假设已自动接入 `/api/graph/ingest`**；未接通的接入契约标为能力缺口，不能伪造统一入口。

执行入口按层区别：

| 层 | 入口 | 证明边界 |
|---|---|---|
| 组件 | `src/graph/index.ts` 的公开 API | 单组件正确性，不证明网络和 Agent 行为 |
| PG 集成 | 真实 PG + pipeline/adapter/engine | 持久化、查询和生命周期，不证明部署 HTTP |
| Graph HTTP | `/api/graph/ingest`、`/document/:id`、`/search`、`/stats` | 应从 Docker 服务调用；Hono `app.request` 另列组件 HTTP 契约 |
| Agent | SaaS session agents + prompt_stream + session event SSE | 工具过程、实际证据、纯最终回答与引用 |

## 2. 隔离、数据与基准

- 使用独立测试数据库；设置 `DATABASE_URL`、`KNOWLEDGE_DATABASE_URL` 为同一测试连接。不要将全套测试连接到业务 `knowledge`，因为部分旧 Graph 测试使用固定 schema，尚未全部迁移为唯一所有权模式。
- 新增场景使用唯一 schema/KB/documentId；清理仅限自己成功创建的对象，规则参照 `test/helpers/owned-schema.ts`。图 HTTP 契约旧脚本还使用固定 documentId，不能在共享业务 schema 上运行。
- 机制 fixture 与真实语料分离。机制原文由测试定义，先冻结原文、版本、必答原子事实和不应出现的事实，再运行模型；不得按模型输出倒推期望。
- 真实语料使用已有 `kb_yingdao_harness_zh_cn` 36 篇原文，只读；校验全库文档 ID、正文/元数据摘要、向量摘要和版本。目标 Graph KB 单独隔离，禁止重新同步后宣称原版本复测。
- 至少两篇文档共享实体和同一关系，另有独占关系、同名异义、否定、数字/单位、顺序步骤、版本条件、无关系实体、空/非法内容和长文多 chunk。准备同 documentId 跨 KB，以及 `doc1` / `doc10` / `doc1_extra`。
- 准备另一 KB 的哨兵实体、边、文档/chunk/RDF/行数据。所有更新、删除、失败清理前后核对哨兵内容，不仅比较条数。

## 3. 主链路用例

每行均要求三类证据：接口/结果、执行过程、PG 最终状态。未实现相应自动化时记 `待实现`，不记 PASS。

| ID | 场景与动作 | 结果与过程预期 | PG/证据断言 |
|---|---|---|---|
| C01 | 已有源语料读取及本轮冻结 | 来源属于指定 KB，原文版本可识别，不触发同步或摄入源库 | 文档、元数据、向量摘要前后一致；目标源 ID 集合固定 |
| C02 | Markdown/text/Tiptap 同事实摄入 | 三种输入均可解析；注入与内置转换路径分别执行 | 每种结果、chunk 原文和图事实匹配各自基准；转换失败不污染图 |
| C03 | 章节、长文、重叠、空章节分块 | 顺序与边界可追踪；原文覆盖；空输入明确失败 | chunkIndex/内容与原文对应，空输入不留下 graph/chunk/checkpoint 半成品 |
| C04 | 真实 LLM 实体与关系抽取 | 数字/条件/否定/方向正确；来源文本确实支持关系 | 逐事实核对抽取结果；实体词面共现不能替代关系忠实性 |
| C05 | 空抽取、超时、429、无效 JSON、fallback | 区分模型故障、合法空结果和降级；重试次数与进度符合配置 | 结果 mode/emptyChunkDocs 与实际一致；不以“请求成功”冒充完整抽取 |
| C06 | 跨 chunk / 跨文档合并 | 同实体去重；同名异义不误并；边方向和重复频率符合 append 契约 | 所有真实来源保留，实体/关系 tracker 指向正确 chunk，嵌入维度有效 |
| C07 | 本体提示、硬校验、Turtle、版本绑定 | 合法实体/关系保留；非法类型/domain/range 明确计入 violations | 本次图/RDF 绑定预期版本，不混入其他版本或 KB |
| C08 | 图、chunk、tracker、RDF 联合写入 | 各存储面均有有效业务数据，不只有空表 | 节点、边、文档关联、chunk、entity/relation tracker、quad 的来源链可闭合 |
| C09 | 图写入/RDF 写入故障并重试 | 失败可分类；无未声明的部分提交；重试可恢复且不重复 | 各表与检查点核对；故障前已有其他文档数据不得被回滚删除 |
| C10 | 检查点中断、续传、内容变更 | 未变化 chunk 可复用；变化 chunk 不能复用旧抽取；成功后清理检查点 | checkpoint 内容 hash、抽取调用次数、最终原文及事实一致 |
| C11 | 图初始化/旧 schema 升级/重复初始化 | 新表列索引正确；重复初始化幂等；并发首请求可控 | 升级前已有图、来源、向量及本体版本内容保留 |
| C12 | 文本查询→嵌入→种子→扩展检索 | 每阶段参数和候选数可解释；邻域深度按约定执行 | 命中真实目标实体与关系，种子/路径/证据均属于目标 KB |
| C13 | topK、空图、严格相关性、结构边排除 | 返回数量遵守契约；锚点追加不能绕过 topK；无实体命中按严格模式返回空 | triplets/entityCards/sourceChunks 分别遵守各自定义，不用端点来源伪造边来源 |
| C14 | 阈值、embedding/LLM rerank 与降级 | 相关与反向向量可区分；全不相关结果不能因排名融合获得高置信度 | 明确距离/相似度含义、边界分数和最终入选结果；已知缺陷不得放宽期望 |
| C15 | local/global/completion/hybrid/round-robin/triplet/temporal | 同一图对照；每种策略的排序、筛选与空结果正确 | 每种策略均独立检查 KB 隔离、来源及 topK，不只检查有返回值 |
| C16 | CoT/查询分解/上下文扩展/边推理 | 子查询重新嵌入；必要时降级；额外模型输出不得伪装原文事实 | trace 可还原子查询与证据集合，解释和事实通道分开 |
| C17 | 原文片段、实体卡、关系证据返回 | 长证据按完整项裁剪；JSON 可解析；Agent 实际看到的内容可重放 | sourceChunk 的文档/索引/正文真实；引用支持相邻结论，关系溯源以边/关系 tracker 为准 |
| C18 | Graph HTTP 校验和错误序列化 | 四端点的合法/缺参/越界/非法 JSON/异常路径状态码一致 | 合法摄入后 PG 有数据；参数错误无写入；并发服务初始化和删除幂等 |
| C18b | 六个关系浏览端点（relations/subgraph/neighborhood/paths/edges/provenance/relation-types） | 只读、强制 KB 作用域、方向/类型/分页/深度/数量上限契约；跨库实体 404；截断显式上报；环与并列边终止 | 端点闭合性（无悬空/跨库边）；来源链以边与关系 chunk 为准，跨 KB 共享 chunk 不回传正文；Docker HTTP 前后 PG 快照只读一致（`test/graph-browse-http.e2e.test.ts` 已实现，Hono+PG 与 Docker 双模式通过） |
| C19 | SaaS 创建会话、注册/选择 graph agent | 使用 V2 `{id,config}` 契约；模型、agent 和 Code Mode 生效 | 新会话独立，session/agent/execution/message 与本题关联；主会话/沙箱绑定正确 |
| C20 | Agent 调工具请求 Graph search | 输入确实是目标接口/KB；输出 HTTP 200、success=true、可解析 | 工具输入、输出和实际可见证据保存；“工具开始”不等于成功检索 |
| C21 | 查询改写、补查、问答澄清与自动代答 | 不泄露答案基准；预算内有证据后停止；问题不会无人应答 | SSE 保存表单及代答；同题工具次数、延迟、终态与证据可追踪 |
| C22 | Agent 最终回答及引用 | 必答事实正确，条件/否定不丢失，无不支持的重要事实 | 仅 `content.type=text` 为最终回答；逐事实关联可见证据及完整文档 ID |
| C23 | 歧义、不可回答、矛盾与提示注入 | 适当澄清/承认证据不足；不把检索失败当功能不存在；不执行证据中的指令 | 不访问其他 KB、不泄露凭据；受攻击前后数据库哨兵不变 |
| C24 | V01–V12 真实语料严格质量门禁 | 每题独立会话，建议 3 次；语义判官校准、分歧人工复核 | 保存原文基准、检索证据、纯回答、逐事实判定；报告逐次结果，不挑最好结果 |
| C25 | 默认 append 与重复导入 | 节点/边不重复；frequency 累计符合现有 append 定义 | 来源、chunk、RDF、检查点的重复处理均有明确契约；不把 append 等同整文幂等 |
| C26 | replace 后检索、证据与回答 | 旧独占事实消失，新事实可检索；旧实体卡/原文不得残留 | 节点/边/frequency/chunk/tracker/RDF 全检查；有 checkpoint 的 replace 同样有效 |
| C27 | replace 中途抽取/嵌入/写入失败 | 明确更新失败后的可见版本；不能宣称未实现的原子替换保证 | 旧/新版本不得混为完整成功；失败恢复后可再检索验证 |
| C28 | 多来源删除、最后来源删除与重复删除 | 删除一篇保留其他来源；最后来源清理；第二次删除安全 | 删除前须预置并证明各存储面非空；删后清理对应图/RDF/chunk/tracker/checkpoint，无孤儿边 |
| C29 | 同 documentId 跨 KB、前缀相似及 KB 删除 | 操作只作用于目标 KB/精确文档；不跨库按前缀清理 | 全部哨兵内容摘要不变，包含来源关联和同名文档的 tracker/RDF |
| C30 | 删除后再问/更新后再问 | 新会话不再使用旧事实；同会话历史影响单独测试 | 新执行的工具结果、最终回答和引用指向当前版本；不把历史答案当新答案 |
| C31 | 多 pod/并发摄入、替换、删除、首请求 | 不依赖单进程缓存保证一致性；互斥/冲突语义明确 | 共享来源完整、无重复业务边和半成品；任意 pod 可读取 PG 状态 |
| C32 | PG 断连、缺表、服务/沙箱重启 | 异常可观测；恢复器不杀进程；进程存活与数据库就绪分开 | 故障前后状态和恢复过程有证据；本轮数据确实恢复后才报告质量 PASS |
| C33 | 资源预算、长文、批量与检索延迟 | 有预算、超时、并发限制；记录墙钟时间，不用并行任务耗时和冒充总时长 | 逐阶段耗时、请求次数、tokens/成本如可获得；压力失败不破坏已提交数据 |

## 4. 扩展功能用例

| ID | 功能链 | 核心断言 |
|---|---|---|
| X01 | OpenAPI / Swagger → operation 文本 → API 图 → 依赖/影响查询 | path/method/schema/operationId 准确；同规格重复与更新、非法规格、按规格删除都验证来源和图 |
| X02 | 源代码 → CodeGraphExtractor → 导入/调用图 → 依赖与反向影响 | 路径与符号作用域正确；代码变更/删除不留旧引用；不同仓库同名模块不串图 |
| X03 | 事件 → 时间图 → functional 冲突 → temporal 查询 | 生效日期、superseded、活动事实及来源准确；未触及节点不被改动 |
| X04 | 会话消息 → SessionDistiller → 合并 → 会话来源追踪 | 空/短对话、role、同名实体、重复蒸馏和删除；不把模型推断伪装用户事实 |
| X05 | RowSchema → PgRowStore upsert → 行检索/过滤 → 自然语言行查询 | 字段类型、筛选操作符、保留字、更新/删除和 schema 隔离；无危险 SQL；接入 Agent 后引用准确行 |
| X06 | 全局上下文索引/摘要 → global 检索 | 更新/删除后的全局摘要不引用旧事实；空图和降级明确；摘要与原始事实分开 |
| X07 | 真值/偏好/反馈 → TruthSubspace/feedback weights → 排序 | 正负/中性和未启用状态分别核对；持久化/重启一致；排序不能突破隔离、阈值和来源约束 |
| X08 | 检索 trace → 持久化 → 答案回填 → 边来源回溯 | trace 与本题 execution 关联，RDF statement/node/edge 文档和 chunk 来源可闭合；多来源删除后正确 |
| X09 | OntologyRegistry/PgRegistry → 注册/切换 → 推理 → 查询 | 版本活动状态、subClass/domain/range/inverse/functional/disjoint；不支持的查询语法明确报错 |
| X10 | RDF fact writer/quad store → 推理 → SPARQL 子集/SQL 编译 → 删除 | named graph 与绑定正确，常量和变量语义正确，查询注入被拒绝，按来源删除精确且跨 KB 安全 |
| X11 | NodeSet/EdgeTypeIndexer → 子图、路径、指标及边类型统计 | 多标签、环、无路径、深度界限与 KB 隔离；删除/替换后统计不引用旧边 |
| X12 | 图 → 可视化/语义布局 → Turtle/N-Triples 导出 | 结构与来源一致；无 embedding 降级、特殊字符转义、blank node/IRI/literal 区分；输出不带其他 KB 数据 |
| X13 | UnifiedStoreEngine 能力组合 → 文档/KB 删除 | GRAPH、可选 VECTOR、RDF/chunk/row 能力按实际接线验证；不支持能力明确失败，部分失败不能默认为完整删除 |

## 5. 流式执行与证据规范

- 先订阅 `GET /api/session/:sid/event`，再提交 prompt；匹配本题 execution。实时呈现状态、工具、文本、表单；模型 reasoning 仅保留测试所需摘要，不能混入最终回答。
- 使用后台执行器和短窗口监视，避免前台长任务中断。表单按字段类型自动代答，记录回答；澄清题允许澄清，但不能提前告诉 Agent 正确事实。
- 每题即时保存 `result.json`，含 session/execution/message ID、模型/配置/图版本、完整 SSE、工具请求响应、可见证据、纯最终回答、引用与逐事实判定。
- PG 前后证据包含目标与哨兵的内容摘要/具体记录。更新删除必须先断言相关记录存在；空集合的“删除后为零”不算通过。
- 可见证据与数据库边来源分别验真；不得用两个端点的所有文档来源替代这条边的来源。
- 模型评估与确定性机制分别报告。`PASS`、`FAIL`、`REVIEW`、`BLOCKED` 分开；skip、未实现或没有证据都不能折算为 PASS。

## 6. 完成门槛与实施顺序

**不能用一个百分比或几个绿色测试代表完整覆盖。** 完成门槛是所有适用 C/X 条目均有明确入口、自动断言和运行证据；不支持的组合记录为能力缺口；已知缺陷不得放宽断言。检查点/隔离/更新删除/事务属于 P0 机制门禁，真实抽取与 Agent 答案属于独立质量门禁。

建议实施顺序：

1. P0：安全隔离 → C08/C09/C10/C13/C14/C26–C29；先补非空前置和失败注入，再修实现。
2. P0：Docker HTTP C18–C23，验证真实请求、工具证据与来源；不得以 Hono request 替代部署验收。
3. P0 质量：恢复或获授权重建语料后执行 C24，按 [严格 Agent 标准](./agent-graphrag.md) 报告 12 题逐次结果。
4. P1：覆盖全部检索策略及 X01–X13，收敛公开 API 与 HTTP 接入边界。
5. P1/P2：多 pod、故障恢复与资源预算，最后形成版本化全链路验收报告。

截至本文件建立：这里是 **33 个主链路场景 + 13 个扩展场景的验收设计**，不是 46 项已实现或已通过。不得把新增表格计入自动化覆盖率。
