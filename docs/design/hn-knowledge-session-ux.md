# 会话中的知识能力：单页信息结构

> 2026-10-26 · 讨论稿 · 配合 `hn-knowledge-product-model.md` 通道四

## 设计原则

1. **无感接入**：用户不选知识库，会话自动挂载；只在必要时暴露"用了哪个库/哪个版本"。
2. **按需升级**：先检索定位，再读正文，最后才做 LLM 综合；每一步都要有可见的下一步动作。
3. **引用必达**：任何结论必须能点到原文的具体块，并带上版本；点不到就视为没有依据。
4. **拒答可解释**：答不了要说清"为什么答不了"，并把问题记成知识缺口。
5. **写回需人审**：Agent 只能生成草稿提案，发布权永远在人手里。

## 会话结构

```
┌───────────────────────────────────────────────────────────────┬──────────────────┐
│ 需求：微前端项目接入引导                       [知识：产品帮助库 v12 ▾]  │  来源            │
├───────────────────────────────────────────────────────────────┤                  │
│                                                               │  ① 接入指南 >    │
│  你：微前端项目怎么接入 Harness？                              │     创建需求      │
│                                                               │     v12 · 3 天前  │
│  ▸ 检索知识（2 次）  产品帮助库 · 命中 5 段          [展开]     │  「打开文档 ↗」   │
│                                                               │                  │
│  AI：接入分三步：创建需求、绑定应用、下发 Harness 配置[1]。      │  ② Harness 配置  │
│      其中第二步需要在应用详情里选择技术栈[2]。                  │     v12 · 12 天前 │
│                                                               │  「打开文档 ↗」   │
│      [1][2] 引用自「产品帮助库 v12」                    [查看]  │                  │
│                                                               │  ─────────────   │
│  你：那如果应用已经存在了呢？                                   │  本轮：检索 2 · 读 1 │
│                                                               │        引用 2 段   │
│  AI：可以复用已有应用，在绑定页选择「已有应用」即可[3]。         │                  │
└───────────────────────────────────────────────────────────────┴──────────────────┘
```

- 顶栏的「知识：产品帮助库 v12」是唯一常驻入口：说明用哪个库、哪个版本，可点开切换/关闭。
- 右侧「来源」是引用的完整视图，默认收起；点 `[1]` 或「查看」展开。
- 底部一行是成本透明：检索次数、读取次数、引用段数——不显示金额，只显示量级。

## 检索升级链

Agent 有三档工具，**默认只到第一档**，需要时才升级。

```
① kb_search          ── 5 段候选（只返回标题 + 摘要 + 分数）
      │  命中不足 / 摘要不够答
      ▼
② kb_get_document    ── 取该文档相关块（不是全文）
      │  需要跨文档综合
      ▼
③ kb_ask             ── 检索 + rerank + LLM 综合，强制带引用
```

每一档在会话里的呈现：

```
▸ 检索知识 · kb_search
  query: 微前端 接入 Harness
  命中 5 段（展示 3）：
    · 接入指南 > 创建需求            0.82
    · Harness 配置 > 绑定应用        0.76
    · 常见问题 > 应用已存在           0.61
                                        [继续读取]  [直接回答]
```

关键交互：**用户可以在中途接管**。「直接回答」= 不再升级，节省成本；「继续读取」= 手动推它往下走。

## 引用组件

三层信息，逐层展开：

| 层级 | 位置 | 内容 |
|---|---|---|
| 角标 | 正文 `[1]` | 序号，hover 显示文档名 + 版本 |
| 悬浮卡 | hover | 文档标题、路径、被引块原文前 2 行、更新时间、「打开文档 ↗」 |
| 侧栏 | 点击 | 全部引用列表 + 每条的原文块（可复制）+ 版本 + 相关性分数 |

引用数据结构（前端渲染所需最小集）：

```
{ docId, docName, path, blockId, release, updatedAt, score, snippet }
```

深链规则：`站点/{kbSlug}/{language}/{docId}#{blockId}?release=v12`，保证打开的是**当时那个版本**。

## 拒答与知识缺口

```
AI：这个问题在「产品帮助库 v12」里没有找到明确依据。

    可能相关（未直接回答）：
    · 常见问题 > 应用已存在       [查看]
    · 接入指南 > 创建需求         [查看]

    [换个问法]   [交给作者补充]   [本次不记录]
```

- 「交给作者补充」：把问题 + 检索轨迹写入 Content Gap，出现在工作台待办里。
- **不允许**用模型常识补齐后不标注；一旦标注"以下不属于知识库内容"，必须显式区分。

## 会话控制

顶栏「知识」菜单：

```
知识来源
  ☑ 产品帮助库           v12（当前）  组织默认
  ☐ 运维手册             仅组织内成员
  ─────────────────────────
  版本：v12（发布 3 天前）  ▾   ← 可回到 v11 复现旧回答
  本次会话不使用知识库
```

- 权限不足的库显示为灰色并标注原因（"仅组织内成员"），不做静默过滤。
- 会话创建后**钉住版本**；若库有更新，在下一轮提示一次「有新版本 v13，是否切换？」，切不切由人决定。

## 写回：草稿提案

```
┌──────────────────────────────────────────────────────────┐
│ 建议新增文档                                   仅草稿     │
│ 《应用已存在时如何接入 Harness》                          │
│                                                          │
│ + 建议放在：接入指南 / 常见问题                           │
│ + 来源：本次会话第 4–7 轮 + 引用的 2 段原文               │
│                                                          │
│ [预览草稿]  [加入草稿箱]  [忽略]                          │
└──────────────────────────────────────────────────────────┘
```

- 默认**不落库**，用户点「加入草稿箱」才创建草稿，且不发布。
- 草稿里自动带来源回溯（哪次会话、哪些消息），作者审阅时能看到依据。

## 状态与降级

| 情况 | 表现 | 是否继续回答 |
|---|---|---|
| 知识服务不可用 | 顶部灰条「知识服务暂不可用」，工具卡标红 | 是，但声明"未检索知识" |
| 库无已发布版本 | 「该知识库还没有发布内容」+ 去工作台 | 是，同上 |
| 检索全低分 | 走拒答流程，不问 LLM | 否 |
| 权限中途被撤销 | 下一轮工具卡显示"无权限"，提示原因 | 是 |
| 版本已过期 | 提示可升级版本，不自动切 | 是 |

## 埋点与指标

| 指标 | 用途 |
|---|---|
| 升级率（search → get/ask） | 判断第一档够不够用 |
| 引用点击率 | 判断引用是否真的被信任 |
| 缺口转化率（缺口 → 新建文档） | 验证闭环价值 |
| 平均检索次数 / 轮 | 成本优化 |
| 拒答后重问率 | 判断检索策略问题 vs 内容问题 |

## 明确不做

- 不在对话流里嵌知识图谱画布（会话是线性阅读，图谱属于工作台）
- 不把整篇文档塞进上下文（按块取，按需升级）
- 不自动发布 Agent 生成的草稿
- 不在会话里做知识库的编辑（只做草稿提案，编辑回工作台）
