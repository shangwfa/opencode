# 知识库与文档编辑：如何焊在一起

> 2026-10-26 · 讨论稿 · 承接 `hn-knowledge-product-model.md`
>
> 结论先说：**文档与知识不是两个产品，是同一份内容的两面。焊点在"块"。**

## 一、三个焊点

| 焊点 | 作用 | 我们已有什么 |
|---|---|---|
| **块锚点** | 引用、维护、跳转都落到同一个块 | 编辑器一级节点已有 `attrs.blockId = blk_<uuid>`，Open API 支持按块读写 |
| **Release** | 站点版本 = 索引版本，可回滚、可复现 | 待补；现在只有单篇 `published` + 异步索引任务 |
| **缺口回路** | 答不上来的问题变成待办，落到具体文档/块 | 待补；现有 `document_sync_tasks` 只记录索引状态 |

没有块锚点，知识侧只能说"这篇文档相关"；有了块锚点，才能说"就是这一段"，并把维护动作直接投递到光标处。

## 二、一个界面，而不是两套

作者视角只有一屏：左边组织，中间写作，右边知识。读者视角是同一屏去掉中间和右边的写权限。

```
┌ 目录 ──────────┬─ 编辑 ───────────────────────┬─ 知识 ──────────────┐
│ ▾ 快速开始      │  接入 Harness                  │ [分块] [召回] [引用] │
│   · 创建需求    │  ─────────────────────────    │                     │
│   · 绑定应用    │  接入分三步…                   │ 本节切分为 2 块      │
│ ▾ 配置          │                                │  ① 148 字 · 已索引   │
│   · Harness     │  ┌ 块 blk_9f2a ────────────┐  │  ②  62 字 · 过短 ⚠   │
│ ▸ 常见问题      │  │ 第二步在选择技术栈…      │  │                     │
│                 │  └──────────────────────────┘  │ 试问：「怎么接入？」 │
│                 │                                │  命中本块 0.82 ✓     │
└─────────────────┴────────────────────────────────┴─────────────────────┘
   [发布 v13 ▾]     站点 ✓ 已同步      检索 ⟳ 1 篇待处理
```

右侧「知识」三个标签页就是"结合"的实体：

- **分块**：这段会被切成几块、多长、是否过短、是否带标题——写的时候就看见"AI 会怎么读它"。
- **召回**：输入一个问题，看当前（含未发布草稿）能不能召回这段；这是作者验证"我写清楚了没有"的最快手段。
- **引用**：这段被哪些问答引用过、被 Agent 引用了多少次、最近一次是什么时候。

读者访问同一个 URL 时，中间变成只读，右栏隐藏——**用权限渲染，不用两套页面**。

## 三、写的时候就给知识反馈

不做事后检测，边写边提示（右侧或行内，不打断输入）：

| 时机 | 提示 | 动作 |
|---|---|---|
| 段落过短 | "这段可能不足以独立召回" | 合并到上一段 / 补充 |
| 标题像问题 | "标题与用户提问接近，利于命中" | 无需动作（正向反馈） |
| 与已有段重复 | "与《配置说明》第 2 段相似 0.87" | 对比 / 合并 |
| 只有图没有字 | "图片内容无法被检索" | 加一句描述 |
| 链接外跳 | "外部链接内容不会被索引" | 复制要点进正文 |

原则：**只提示，不自动改**。作者永远有最终决定权。

## 四、发布：一个动作，两个产物

发布按钮右侧下拉，展示即将发生什么：

```
发布 v13
├ 站点     ✓ 更新 3 篇（立即生效）
├ 检索     ⟳ 2 篇待索引　⚠ 1 篇上次失败
├ 检查     空文档 1 · 过短 4 · 重复 2
└ [仅发布站点]   [发布并重建索引]   [先预览]
```

- **发布抽屉**必须在点之前可见，而不是点完才知道失败。
- 两个产物允许差集：站点立刻生效、检索异步；界面上用"站点 ✓ / 检索 ⟳"两个独立状态表达，永远不合并成一个"成功"。
- **预览**：草稿以站点样式打开（带 `?preview=release`），不进公开、不进索引。

## 五、维护：从"感觉要更新"到"知道该改哪一段"

工作台的知识页不再是文档列表，而是**问题清单**，每行都能跳到具体的块：

```
知识健康 · 产品帮助库
┌────────┬──────────────────┬──────────────┬─────────────────────┐
│ 类型   │ 位置             │ 依据          │ 操作                │
├────────┼──────────────────┼──────────────┼─────────────────────┤
│ 缺口   │ 常见问题         │ 7 天 12 次未命中 │ 创建草稿（带问题）  │
│ 过短   │ 接入指南 > 步骤3  │ 62 字，无法独立召回 │ 跳转到块         │
│ 陈旧   │ 配置说明          │ 最常被引用，45 天未更新 │ 查看引用记录   │
│ 重复   │ 两篇同名          │ 相似度 0.91      │ 对比并合并          │
│ 失败   │ 部署指南          │ 索引失败 2 次    │ 查看原因 / 重试     │
└────────┴──────────────────┴──────────────┴─────────────────────┘
```

这张表是"文档编辑"和"知识库"真正结合的地方：**维护的输入来自使用数据，而不是作者的记忆**。

## 六、草稿与索引的关系

明确三条规则，避免作者困惑：

1. **草稿不进检索**（默认），但**可以在召回面板里"试问"**——只对作者可见。
2. **发布才进索引**，异步执行，失败可单独重试，不影响站点。
3. **编辑已发布文档**时，检索继续用上一版；右栏明确标注"检索中的是 v12，当前是草稿"。

## 七、落地顺序

**P0（最小可感）**

- 块锚点打通：引用带 `blockId`，点击跳回正文对应块
- 发布抽屉：站点/检索双状态 + 失败可重试
- 右栏「分块 + 召回」：作者能验证"这段能不能被找到"

**P1**

- 「引用」标签：这段被引用多少次、来自哪些问题
- 知识健康清单（缺口 / 过短 / 陈旧 / 重复 / 失败）
- 发布前检查（空文档、重复、过短）

**P2**

- 行内写作建议（重复检测、图片无描述）
- 缺口 → 一键生成草稿（带问题与检索轨迹）
- 读侧热力图：哪些块被读得最多（指导重写）

## 八、明确不做

- 不做"两套编辑器"：写作用一套，预览用只读渲染
- 不做自动改写正文（只提示）
- 不做发布即自动全量重建（按变更集增量）
- 不在写作界面里塞图谱画布（图谱属于工作台的知识页）

## 九、需要确认

1. **右侧知识面板放哪**：写作界面内嵌（推荐，结合最紧），还是独立"知识"页签（干扰更小）？
2. **草稿是否允许试问**：允许（推荐，作者能自测）还是严格隔离？
3. **发布默认行为**：默认"发布并重建索引"，还是默认只发站点、索引手动触发？
