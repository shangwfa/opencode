# Chat 输入区精修（2026-10-30）

> 下文先记录首轮输入框精修；整页 Oriel 方向及最终样式以文末第二轮记录为准。

## 方向

让输入框成为轻量工作区，而不是聊天下方的巨大表单。主动作是写消息与发送；模式、模型和附件保持可见，但降低视觉权重。只优化共享 Composer，不改消息流、请求协议和滚动机制。

## 实际参考与取舍

通过 Ego Lite 查看 https://chatgpt.com/ 与 https://gemini.google.com/app 的真实首页。Claude、Perplexity 遇到安全验证，不算已验证参考。

- ChatGPT 短消息使用紧凑单行，避免未输入时预留大块空白。
- ChatGPT 附件用左侧无边框加号，不做独立工具卡片。
- ChatGPT 将次要设置放在右侧，输入文字是视觉起点。
- ChatGPT 主操作用圆形，和次要文字按钮形成区别。
- Gemini 同样以低矮的输入容器为核心，内容增长而非默认撑高。
- Gemini 模型选择为轻量文字与下拉箭头，没有厚重独立外框。
- 两者都把容器轮廓弱化，避免和正文竞争；不照搬 Gemini 首页蓝色氛围或语音入口。
- 我们多了工作模式，保留紧凑双层布局：上层输入，下层左侧附件与模式、右侧模型与发送，不强塞成单行。

## 实现

- 空态实测 108px，多行内容驱动增高；宽度沿用 max-w-3xl。
- 20px 容器圆角、轻微灰底、单层细边框，无外框阴影。
- build / plan / general 分别展示为执行 / 规划 / 通用，菜单仍展示技术标识；未知模式原样保留。
- 发送和停止使用固定尺寸圆形按钮，禁用态不再整块重灰。
- 保留图片添加、预览与移除、粘贴/拖放、模型选择、上下文用量及中文输入法保护。
- 聚焦时仅边框与底色轻微过渡，遵循减少动态效果设置，不引入高度或位移动画。
- 占位文案缩为“输入消息，开始协作…”，不增加快捷键说明或不支持的工具入口。

## 第二轮：Oriel 风格自由对话页

用户指定参考：<https://dribbble.com/shots/27753932-Oriel-AI-Financial-Intelligence-Dashboard-Animation>。实际打开并查看了 15 秒动画的整体布局与局部帧，不将金融业务组件搬入聊天页。

### 北极星与范围

冷灰工作空间承托白色阅读面，蓝紫色只强调 AI、当前项与主动作。整页围绕阅读和输入组织，不用卡片把每条回答分割。

- 仅 `/free-chat` 与其会话子路由应用主题，不改全站根令牌、官方 `packages/app` 或服务接口。
- 保留系统中文正文字体、Lucide 图标与现有组件；空态标题使用系统中文衬线回退，不下载字体。
- 共享 Composer / Timeline / Markdown 增加样式定位标记；Oriel 视觉仅在自由对话容器内生效。
- 浏览器工作区复用 `FreeChatCore`，共享的紧凑页头和空态结构会同步，但不应用本页冷灰主题。

### 修改

- 全局导航在此路由收为白色圆角轨道，当前项蓝色；左侧历史保留在开放画布，选中项白底。
- 白色主面板、轻分隔页头、用户浅蓝紫气泡、15px/1.85 正文与更明确的标题节奏。按用户反馈移除每轮回答前的圆球与 OpenCode 身份标记，直接呈现思考过程和正文；页头与侧栏标识保留。
- 输入区轻描边和柔和阴影，聚焦蓝紫描边，发送/停止入口维持固定尺寸。
- 修正 Radix 内容包装的表格宽度扩张；只在本页允许长表格内部横向滚动。
- 窄屏侧栏以覆盖层展开，提供关闭按钮及遮罩；收起后 inert，避免不可见项接收键盘焦点。
- 沿用悬停/聚焦与桌面侧栏宽度过渡；移除消息位移入场，窄屏侧栏不做宽度动画，减少动态偏好下关闭过渡。

### 独立视觉评审

一轮存量界面评审，不打分。三条反馈均处理：空态组向输入区靠近、提高历史标题对比、删除重复身份文案。移除“AI 工作空间”“你的 AI 协作伙伴”“从一个问题开始，让想法更进一步。”；保留中文衬线提问标题、阅读面与紧凑输入框。没有将未验证的动效视为通过。

### 验证

- 作用域单测覆盖 `/free-chat`、会话子路由和其他路由，防止样式扩散。
- 浏览器检查桌面会话与空态、390px 窄屏、暗色、侧栏关闭/遮罩、桌面上下文 dock 与窄屏上下文 dialog。
- 窄屏实测视口/文档宽均 390px，阅读区 326px、输入框 302px，不再由长文撑宽页面。
- 新主题下真实组件持续追加模拟连跑 3 次：跟随阶段新增高度均 278px、距底最多 0.5px；上滚后新增高度均 318px、位置波动 0px；发送新消息后新增高度均 318px、距底最多 0.5px，底部按钮未闪现。临时诊断模块已移除。

- 最终效果、基线与参考截图位于 `packages/hn-base-server/artifacts/chat-oriel-20261030/`，不入库。

## 第三轮：紧凑会话列表

按用户确认的方向替换第二轮双行列表：移除重复图标和逐条日期，采用“今天／昨天／更早”分组；无会话的分组不显示。每条标题一行、38px 行高、2px 间距，长标题省略并保留 title 完整提示；选中项使用浅蓝紫底色，无边框和阴影。顶部会话标题缩为 17px，品牌区不变。

## 第四轮：下拉菜单风格对齐

- 根因：下拉菜单经 Portal 挂到 `body`，不继承 `.chat-shell` 的局部令牌，因而仍是全局灰色与默认选中态。
- 处理：输入框的 Agent 与模型菜单使用全局 `.chat-menu`，直接写入同一套白色、浅灰与蓝紫色；深色模式使用对应取值。
- 实测：模型菜单背景 `rgb(255,255,255)`、圆角 16px，12 个模型项正常，当前项为蓝紫色。截图：`packages/hn-base-server/artifacts/chat-oriel-20261030/model-menu-aligned.png`。
- 浏览器面板整体重做（第五轮）：标签页保留，收为轻量标签栏；导航与地址合并为一行，接管改为带文字的胶囊按钮；画面放入统一白色圆角框，状态移到画面左上角小标签；移除原先的浅紫色多层背景。截图：`packages/hn-base-server/artifacts/cdp-ui-20261030/browser-panel-redesign.png`。功能与标签、接管、远程键盘、粘贴、滚轮和导航保持不变。
- 同次移除 Browser Use 首页的「执行流程」与「UI 走查」入口。脚本库的「执行流程」仍通过 `?script=` 带入流程，输入区显示可取消的流程标签；走查提示已从 `browserPrompt` 删除。
