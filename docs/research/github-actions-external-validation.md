# 后续考虑：GitHub Actions 作为外围验收系统

- 记录日期：2026-10-26
- 状态：待评估，暂不实施；用户认可该方向，未确定具体方案。

## 思路

保留 SaaS 与会话沙箱现有职责，让 GitHub Actions 对代码提交或 PR 进行独立验收，不把 Agent 主执行流程迁移到 Actions。

- OpenCode SaaS：会话管理、模型调用、任务编排。
- 会话沙箱：代码读写、工具执行、开发过程中的测试。
- GitHub Actions：提交或 PR 的独立测试、构建、静态检查与验收结果留存。
- 人工审批：高风险合并与发布的最终控制。

## 预期价值

- 在 Agent 自测之外提供可复查的验收证据。
- 借用 GitHub 的运行日志、Artifacts、PR 检查与分支保护能力。
- 让验收结果关联具体提交，便于追踪失败与复现问题。

## 后续评估事项

- 触发方式、仓库授权、最小权限及不可信 PR 的凭据隔离。
- 检查结果回传 SaaS、提交 SHA 关联、重复事件与重试处理。
- 单测、接口测试、E2E 及 PG 数据断言所需的隔离环境与成本。
- 明确必过检查与人工审批边界，避免仅凭 Agent 自述判定成功。
- 运行时长、并发、额度和敏感日志处理。
- 可选探索变异测试，检验测试是否能识别故意引入的错误。
