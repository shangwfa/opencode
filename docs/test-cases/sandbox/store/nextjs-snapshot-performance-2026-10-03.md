## 解读与后续验证点

- 依赖安装和快照分开计时。首次核心依赖安装加创建检查点合计为 84.01–86.87s；增装 UI 依赖加检查点为 46.17–85.61s。下载阶段实测有 registry 慢请求/重试，不把这段当成快照耗时。
- 安装核心依赖后，工作目录约 650.87MiB、20,056 个文件；UI 扩展后约 764.36MiB、31,508 个文件。含下载 store；`du` 是文件系统报告值，不等于镜像新增物理存储。
- 同沙箱修改两份源码，快照合计仍为 43.03–56.73s；不能假设“改几行就只花几行的成本”。从含依赖快照恢复再修改，合计 19.02–40.34s；恢复本身为 0.85–1.39s。这是本地两样本观测，不承诺固定加速比例。
- API 接受请求约 0.04–0.09s，但 Ready 需要等待数十秒；不能用创建接口返回耗时代替快照完成耗时。
- 去掉下载 store、保留源码和 node_modules 后，工作目录约 380.78MiB、16,071 个文件，检查点为 25.88–27.78s；保留 store 时为 38.80–43.49s。代价是失去该会话的离线重装缓存：有缓存重装仅 1.05–2.16s。不能据此直接开启生产删除 store；当前 prune 白名单也不包含它。
- 已安装依赖时，多数 CLEAN 判定为 1.39–5.21s，可以省掉数十秒远端创建。但缓存重装场景曾出现一次 15.82s、未确认 CLEAN；补测为 1.42s/CLEAN。尚未定位为内容变化还是扫描失败，需单独复现，不能称为已解决。
- 本次没有运行 next dev/next build，不含 `.next` 构建缓存、运行中后台写入或并发安装；不代表这类负载的性能与一致性。
- 脚本已改为每轮立即释放测试产物，并在可用磁盘少于 10GiB 时拒绝开始。原主容器已恢复启动，其他已有停止容器未操作；残余 Creating 快照仍需平台对账处理。
