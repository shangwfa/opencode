# PVC / snapshot 对 code-agent 执行无负面影响：V2 验收用例

## 目标与状态

验证持久化方式不会导致 code-agent 错读文件、漏写或重复执行、误报成功、越界执行、错误恢复、提前销毁源沙箱或破坏运行中的任务。

**本文件是新增验收设计，全部用例待执行，不是通过报告。** 既有快照 shell/API/PG 实测只能作为局部证据，不能替代真实模型、code-mode、子会话和故障场景验收。不修改实现，不自动切换共享服务配置，不执行故障注入。

两种模式互斥。允许底层保存范围和耗时不同，但不能隐瞒能力边界；“无负面影响”不等于零延迟、容器永不暂停、进程可跨销毁存活或任意节点故障零数据丢失。

## 一、执行矩阵与公共前置

| 组 | 环境与用途 | 要求 |
|---|---|---|
| PVC | Docker SaaS + OpenSandbox + 专用 PVC，PG 本地测试库 | 每个测试会话显式 `sandbox.persistMode=pvc`；默认 session 隔离 |
| Snapshot | 同版本 SaaS/OpenSandbox，专用会话 | 显式 `sandbox.persistMode=snapshot`；无 PVC 挂载 |
| 基线 | 每种模式下无测试主动检查点/销毁的相同任务 | 默认生产生命周期仍开启并记录，不能称为完全禁用持久化 |
| 干扰组 | 每种模式下施加保存、回收竞争或故障 | 使用同一任务/fixture，对照终态、文件与执行轨迹 |

公共步骤：

1. Docker 中运行 SaaS，连接 `127.0.0.1:5432/opencode-v2-up`，确认 API、模型、OpenSandbox、对应存储可用。认证仅通过安全环境变量注入；不可将凭据写进证据。
2. 固定服务镜像、源码提交、OpenSandbox版本、模型、权限、资源、区域、依赖锁文件与超时。记录有效配置与容器健康；unhealthy 必须说明原因或判环境阻塞，不能忽略。
3. 准备唯一 runID；每个用例创建新会话、任务marker和明确的清理清单。故障用专用实例/测试库，不能影响他人会话或改共享 Registry/PVC。
4. 默认 code-mode 开启：记录工具目录和有效 `OPENCODE_CODEMODE_EXECUTOR`，默认是 sandbox。必须看到实际 `execute` 及其 `toolCalls`，不能只检查配置或把 shell API 运行称为 code-mode 验收。工具路径以当轮目录为准，禁止猜名称。
5. 通过 SaaS API驱动；真实 Agent 使用 prompt/wait/message/log，确定性检查使用 session shell 和文件 API。先订阅日志，再发请求，按消息/工具调用标识关联，避免拿另一命令的结束事件当结果。
6. 对每种模式记录 `/proc/self/mountinfo` 和 PG有效 `sandbox.persistMode`。PVC核对 claim/subPath、七个持久化路径及独立包缓存；snapshot核对这些路径位于rootfs、无PVC，不仅看请求字段。
7. 持久化公共目录为 `/workspace`、`/resources`、`/home/sandbox`及其 `.cache/.config/.local/tmp`。系统目录、`/tmp`、外部挂载及未配置目录不能默认视为两种模式都持久。
8. 基础 fixture 包含Git仓库、普通/空/二进制文件、空格/中文路径、symlink/hardlink、执行权限、home/resources配置，以及工作区内 pnpm store。依赖安装使用pnpm和淘宝源；实际源URL带/不带尾斜杠等价。

不得为了保证通过而关闭 code-mode、隐藏失败、只用 shell 替代模型工具、把 snapshot 混挂PVC，或让另一种模式偷偷负责数据保留。

## 二、每项必须收集的证据

- **结果**：工具/回合真实终态、exit code、文件SHA-256和清单、Git diff、构建/测试结果。缺工具调用或模型未遵从步骤，应标模型执行失败/阻塞，不能用回答文字判通过。
- **过程**：真实 `execute`/内部调用状态、工具顺序与重试、沙箱ID代际、进程PID与启动时间、stdout/stderr和断流、检查点/回收时间线。服务器容器文件不能冒充远端文件。
- **PG**：`session_v2`模式/父子关系、`sandbox`实际所有权/状态/代际、`session_snapshot`来源与状态、`snapshot_operation`队列状态/attempts，以及真实消息/事件持久记录。字段与终态以当前schema为准，不使用V1 exec_log。
- **性能**：排队、模型推理、工具开始至结束、保存、销毁、恢复、首条命令、校验、构建分开计时；报告失败率、原始样本、范围和中位数，不把三个样本当可靠P95。

只读PG核验不得改生产行。恢复点查询限定session scope，接受ready/stale：stale可能表示已经恢复过，不能据此判数据丢失。显式POST snapshot无队列attempts，不能套用snapshot_destroy统计。

## 三、公共执行语义（每项分别跑PVC、snapshot）

### CA-PERSIST-01（P0）模式与执行位置真实生效

**步骤**：创建对应模式会话；实际Agent通过code-mode调用shell输出cwd/hostname，写入唯一marker；读取挂载信息，并在SaaS容器及宿主机核对marker未落本地。随后Agent读回marker。

**断言**：cwd为/workspace；写读发生在所属远端沙箱；PG模式和挂载一致；无隐式local/另一持久化模式回退。缺execute或executor错误不能通过。

### CA-PERSIST-02（P0）完整开发任务与多轮延续

**步骤**：Agent检查Git项目、修改业务代码、补测试、运行测试与Next.js构建，再发送下一轮需求继续修改。基线与干扰组使用同一fixture；干扰组由正常回合检查点/生命周期触发持久化。

**断言**：最终业务测试正确；消息中的真实工具执行成功，文件与diff匹配；保存没有多建业务沙箱、回滚上一轮文件或导致重复补丁。推理措辞/随机生成的build ID不要求逐字相等。

### CA-PERSIST-03（P0）code-mode串行与并行工具组合

**步骤**：Agent在一次execute中依次写→读→修改→shell验证；另一次用Promise.all并行处理两个互不相干文件。在内部调用之间触发正常保存请求。

**断言**：await依赖顺序正确；所有完成状态与实际结果一致；内部调用始终属于同一会话/沙箱；未完成调用不能被外层execute误报为全部成功。并行只测独立文件，不预设同文件无锁写是安全的。

### CA-PERSIST-04（P0）文件工具与shell/API双向可见

**步骤**：Agent用write/edit/read/glob/grep及实际暴露的patch操作；shell与文件API交叉读取。反向由shell写入，再由Agent读取编辑；保存/恢复后重测。

**断言**：不存在本地/远端分叉、旧句柄读旧代际、缓存读到旧内容。模型不暴露patch时，该子项记不适用并说明，其他工具不能跳过。文件API本身不boot沙箱，先用真实工具/boot建立实例。

### CA-PERSIST-05（P0）文件拓扑、权限及删除语义

**步骤**：Agent运行fixture校验；修改同大小文件并恢复mtime、改链接目标、chmod、rename、delete，保存后重建再验证；覆盖中文与空格路径。

**断言**：内容/权限/链接及删除结果正确；不会因mtime未变误判CLEAN。硬链接按inode关系核验，不能仅比较两个文件hash；空目录作为业务输入需保留，否则判兼容性缺陷，不能因manifest忽略目录而豁免。

### CA-PERSIST-06（P0）Git状态、依赖与构建可继续

**步骤**：准备tracked/untracked/删除文件与Git索引；pnpm安装后保存恢复。Agent执行git status/diff、依赖解析、测试与build，再新增一个依赖。

**断言**：分支、索引、diff、锁文件与node_modules拓扑可用；依赖无跨文件系统链接失效。冷/暖缓存分别记录，不把重新下载失败误归为模型失败。包缓存可共享不等于工作区可共享。

### CA-PERSIST-07（P0）持久化范围对Agent明确

**步骤**：写入七个公共持久目录、/tmp及系统目录标记，安装一项系统工具；记录声明范围，再保存重建，Agent检查工具与配置。

**断言**：公共目录与Agent凭借它们继续工作的能力保留。PVC范围外系统修改若不保留，应预装到基础镜像/有明确重建步骤或判该任务不受支持；不得静默丢失后报成功。快照也不得承诺外部挂载进入rootfs快照。此项验证边界透明，不要求PVC凭空保存所有rootfs。

### CA-PERSIST-08（P0）主会话与task子会话共享

**步骤**：主Agent经task创建子会话，父子分别写不同marker，主会话读取子任务结果；子任务运行期间触发父会话正常持久化/回收竞争。

**断言**：父子真实工具使用同一主沙箱ID；PG父子关系与沙箱所有权正确，不要求子会话一定有独立sandbox行。子会话结束不能销毁父沙箱，子任务不能触发业务沙箱rebase。fork不是task子会话，不混用其契约。

### CA-PERSIST-09（P0）无关会话与共享app边界

**步骤**：两个无关root会话使用同名文件与不同marker，并发读写/保存/恢复，确认无法互读。PVC另建同appId的显式app模式会话验证其声明的共享；不同appId验证隔离。

**断言**：默认session隔离成立，包缓存不串源码/配置。app共享是PVC专属声明，不将它误判为隔离失败，也不要求snapshot提供未经实现的app共享。共享目录的同文件竞争必须报告，不以last-write-wins当无损保证。

## 四、保存与生命周期不破坏运行中任务

### CA-PERSIST-10（P0）长命令与保存并发

**步骤**：Agent启动持续输出编号并写结果的60秒命令，记录PID/启动时间；在运行中触发后台正常保存，snapshot另触发显式检查点；PVC观察对应正常保存/卷状态路径，不强行调用snapshot接口。

**断言**：保存不能杀进程、换代际、丢输出或误报退出0；结果编号/文件完整。平台可能短暂freeze，记录最长输出间隔并按约定预算判定，不要求物理零停顿。

### CA-PERSIST-11（P0）活跃构建、安装和文件写入期间检查点

**步骤**：分别在pnpm install、Next.js build、跨文件版本写入过程中发起保存，继续等待原任务。跨文件fixture采用应用锁或事务定义v1/v2一致版本，再恢复检查。

**断言**：运行任务不中断、构建无半截依赖/损坏产物。不得将普通文件系统快照宣称为跨文件事务；无法协调时应延迟保存/拒绝安全销毁并暴露不确定状态。不得恢复混合版本后误报成功。

### CA-PERSIST-12（P0）后台服务与持续连接

**步骤**：Agent启动开发服务器及心跳进程，记录PID/启动时间、HTTP响应和连接；多轮工具调用及检查点并发，持续探测；区分后台进程启动成功与服务readiness。

**断言**：正常持久化不擅自重启/rebase业务沙箱，不断开服务来换取更快检查点。实际发生连接失败/暂停应记录并对照预算；explicit销毁后的服务重启属于下一项，不冒充连续运行。

### CA-PERSIST-13（P0）活跃任务与idle/TTL/显式销毁竞争

**步骤**：独立服务采用短idle/TTL，Agent及task运行长命令；临近回收窗口刷新活动。另在活跃写入时调用kill-sandbox，记录系统阻止/等待/中断策略与全部终态。

**断言**：后台回收不能把活跃任务判idle；TTL保护/续租失败须可见。显式kill不得无声摧毁活动写入：按产品策略等待安全点或明确拒绝；若允许用户显式中断，必须明确Interrupted/Cancelled而非Succeeded，并满足数据保护门槛。保存结果要绑定被销毁的同一代际。

### CA-PERSIST-14（P0能力门槛）PTY执行位置与连续性

**步骤**：先核验PTY进程是否确在session sandbox。若具备能力，交互运行持续程序，检查点同时发送输入、resize与重连，比较PID、会话和输出。

**断言**：保存不杀PTY、不丢输入或串会话；不得退回SaaS本地PTY伪装通过。当前[PTY文档](./sandbox-terminal.md)记载V2接口位于Server本地：若仍如此，本项标**能力阻塞**，不能标PASS或据此声称已覆盖沙箱PTY。

### CA-PERSIST-15（P0）回合终态：成功、中断与失败

**步骤**：分别让Agent完成修改、执行失败命令、用户中断长任务；每种都观察正常回合检查点、队列收敛和下一轮读取。用实际事件触发，不手工伪造终态。

**断言**：文件保留与真实执行一致；失败/中断不被保存逻辑改为成功。保存失败必须在操作状态/日志可辨识，不要求已完成业务命令被改写为失败，但不能据Succeeded推导“数据已持久化”。队列不得永久running。

## 五、恢复后继续执行与故障保护

### CA-PERSIST-16（P0）安全销毁后恢复继续开发

**步骤**：Agent完成任务并保存，记录hash/配置；无活动命令时kill，下一轮由真实Agent读取旧代码再修改、测试和build。

**断言**：新代际/持久化来源正确、文件无丢失；工具重新绑定新代际。内存/进程不要求跨销毁保留，服务按声明启动步骤恢复；未声明的进程恢复不能假装成功。

### CA-PERSIST-17（P0）重复恢复与连续多代

**步骤**：同一数据状态安全销毁恢复两次，再小改保存恢复，连续三代；每代用真实Agent完成读写验证。

**断言**：snapshot已消费stale检查点仍可恢复，实际平台snapshotId和PG来源匹配；PVC一直挂预期subPath。没有错误cold start、旧配置回退、错误清理仍引用的数据或循环创建沙箱。

### CA-PERSIST-18（P0）dirty源保存失败，禁止降级丢修改

**步骤**：先建立v1有效恢复点，Agent写v2；仅在专用故障环境让最终快照create/upload/Ready查询失败，或PVC写入/fsync/挂载持久化确认失败；发起安全回收，覆盖首次和最终队列重试。

**断言**：未证明v2受保护前保留dirty源或明确阻止销毁；不能因为有v1就最终销毁唯一v2来源。snapshot_operation的attempts达到上限也不豁免。若当前实现降级接受旧恢复点后销毁，**判P0失败**，保留源和证据，不把该行为作为通过标准。

### CA-PERSIST-19（P0）恢复失败不隐式冷启动

**步骤**：保留唯一有效数据；snapshot注入拉镜像/恢复创建失败，PVC注入mount/claim访问失败，随后Agent尝试读取旧文件。故障解除后重试。

**断言**：错误如实反馈，不创建空rootfs代替原状态、不丢恢复点、不转另一模式。boot接口即使返回HTTP200也需检查非空sandboxId与PG running；解除故障后恢复原数据。

### CA-PERSIST-20（P0）PG/平台查询失败不可当无恢复点

**步骤**：专用环境临时使恢复点/挂载配置PG查询失败，以及平台status查询超时；触发重建或回收，故障恢复后对账。

**断言**：查询错误不等于不存在数据，不触发cold start或忽略保护条件销毁；返回错误/待重试状态明确。客户端超时不代表平台操作未执行，需重新查询实态与原代际。

### CA-PERSIST-21（P0）预算超时、迟到成功与重试副作用

**步骤**：设明确工具/恢复/保存预算，以受控延迟让客户端先超时、远端后成功；使用唯一业务marker和追加计数识别重复写。重连并对账，再由Agent决定继续。

**断言**：结果未知与确定失败可区分；旧请求不能覆盖新代际，迟到沙箱不能泄漏。禁止盲重试追加/提交等非幂等业务；可以保证不到exactly-once，但必须暴露不确定性，不假报零次或一次。

### CA-PERSIST-22（P0）SaaS重启与运行中会话恢复

**步骤**：专用SaaS实例执行真实Agent任务，分别在保存进行中、工具执行中重启服务；保留远端沙箱，不直接杀其进程。重连message/log，下一轮核对文件、任务与操作状态。

**断言**：PG与平台状态可对账，重启不能把未知执行改为成功或重复提交业务修改；不要求推理/内存原地续跑。仍存活的后台服务不应被错误创建新代际替换；最终保存/队列状态必须收敛或明确失败。

### CA-PERSIST-23（P0）断流、回连与错误可信度

**步骤**：Agent长任务期间只断开客户端SSE连接，再按持久日志序号回连；另执行exit非零、权限拒绝、文件不存在和模型请求失败。

**断言**：断客户端不等于任务必然取消；输出/终态不丢不串，失败保持真实类别与上下文。不得暴露凭据、宿主文件路径或用持久化错误遮蔽原始业务错误。

### CA-PERSIST-24（P0）并发保存/销毁/恢复及跨实例竞争

**步骤**：同一会话并发发保存、kill和boot；另用两个专用SaaS实例共享PG发竞争请求，按唯一marker验证。只用进程内互斥的单实例结果不能代替跨实例测试。

**断言**：业务最终只使用正确代际；创建合并/fencing/CAS和操作对账防止旧操作误杀新实例。每条已接受操作有可解释终态，失败不丢唯一数据。不得把当前跨实例能力未证实写成已通过。

### CA-PERSIST-25（P0）磁盘/存储压力与OOM

**步骤**：专用存储设置测试配额，覆盖ENOSPC/只读、依赖安装中进程OOM、节点/存储不可达；节点故障需要明确平台授权，不用断SSE冒充。保留故障前已确认恢复点。

**断言**：写入失败/进程死亡真实反馈，不报安装/保存成功。可恢复范围和RPO明确；未经checkpoint的rootfs修改不得承诺幸存，PVC也不能承诺未落盘修改零丢失。不自动覆盖残存数据，失败保留用于恢复诊断。

### CA-PERSIST-26（P0）清理与保留策略不会删除仍需数据

**步骤**：专用会话保持活动子任务/恢复引用，在保留清理窗口验证不误删；完成任务后仅删除本用例会话，复核平台实例、PG操作和存储引用。

**断言**：父/子生命周期不误删父数据，恢复点GC不删除正在使用或唯一受保护版本；失败资源保留。session删除是否保留PVC、Registry镜像按明确策略核验，不假设API删除即物理回收全部数据。

## 六、性能不降低可执行性

### CA-PERSIST-27（P1）同任务基线与保存干扰对照

**步骤**：每种模式各至少三轮，交错跑基线/干扰组，固定代码与依赖；保存与Agent长命令/构建交叉。分别统计推理、工具、检查点、最长输出停顿和首次恢复build。

**断言**：无新增非预期失败/中断/重复副作用；性能满足执行前书面确定的绝对预算与基线退化上限。预算未设只能报告数据，不能声称性能验收通过。小样本不足以证明零失败率或稳定P95。

### CA-PERSIST-28（P1）多会话持久化压力下公平性

**步骤**：受控并发运行多会话，部分保存大项目，另一些Agent执行短read/shell及code-mode组合；资源/并发上限先确认，逐级增加而非无限压测。

**断言**：大快照/卷I/O不导致无界排队或其他会话饥饿；超时与限流可见；无串数据、异常回收或模式回退。记录吞吐、等待和错误，未达到平台能力或预算则阻塞/失败，不靠增加超时掩盖问题。

## 七、验收门槛与结果模板

发布门槛：所有适用P0分别在PVC与snapshot验证；任何静默丢失、错误成功、越界、dirty源保护失败、活跃任务被后台杀死均阻断发布。能力阻塞不等于通过；PTY等尚未支持的能力需明确产品范围，不能据此宣称全场景无影响。P1须有约定性能预算并满足，不能仅靠“正确但无限等待”。

每项记录：`runID / 用例ID / 模式 / 版本与镜像 / 模型与code-mode证据 / 前置条件 / 操作时间线 / API与工具终态 / 文件与构建 / PG与平台 / 分阶段耗时 / PASS或FAIL或BLOCKED或NOT_RUN / 失败资源ID / 证据路径`。

初始状态：CA-PERSIST-01至28全部NOT_RUN。模式专属子项可标NOT_APPLICABLE并说明依据，公共P0不得用其替代BLOCKED。汇总按模式分别列通过/失败/阻塞数量，不能把某模式结果复制给另一模式。

发现问题先保留证据并讨论解决；修复后用新runID完整重跑失败用例及相邻回归。旧失败记录不删除、不混入有效性能样本。清理仅限明确测试ID，失败默认保留，禁止清理唯一恢复来源或执行泛化数据库/存储删除。
