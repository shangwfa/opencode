## 发现

1. **spec 笔误**：`health-and-session.md` 写 `project.id` 为 32 位 hash，实测 40 位 sha1 hex（行为正确）。
2. **watchdog 需显式配置**：Pod 须设 `OPENCODE_WATCHDOG_TIMEOUT_SEC=1` 与 `OPENCODE_WATCHDOG_SCAN_INTERVAL_SEC=1`，
   否则默认长超时不触发，T-WDT.V2.1/V2.3 会假失败。补配后 3/3 通过。
3. **session-permission T5.6 flaky**：`promptAndAutoReply` 并发轮询 pending 窗口，首次可能错过；重跑通过。
   建议改为订阅式等待。
4. **session-e2e-stream 需沙箱**：SaaS 镜像无 `python3`，T10.1 依赖它；沙箱镜像有 `/usr/bin/python3`。
5. **`POST /command` 执行链正常**（曾误判为缺陷）：早前判定"子会话未创建"是探针查错库——Pod 连
   `opencode-v2-up`，脚本/探针查 `opencode-v2-test`。正确库上 subagent 子会话与普通 command 消息均正常产生。
   **教训：跑库相关脚本前必须核对 `docker exec <pod> printenv OPENCODE_DATABASE_URL` 与 `PG_URL` 一致。**
6. **`POST /api/session/:id/generate` 曾报 TLS 失败（已结案：环境问题）**：首次测试返回 503
   `UNKNOWN_CERTIFICATE_VERIFICATION_ERROR`。网络重连后同一请求 **HTTP 200**，答出上下文中的 `ALPHA-77`，
   且主消息数不变（`before=after=3`，"临时问答不落主对话"成立）。判定为当时自签/代理证书的瞬时连接问题，
   **非产品缺陷**。
   另记契约：请求体是 `{prompt: string}`，响应 `{data:{text}}`；传 `text` 会 400 `Missing key at ["prompt"]`。
7. **session-resources-owner 13/14（失败疑似脚本路径过时）**：`REPORT=` 定位进化：
   `command did not create an internal child`（库错配，已撤销）→ `child executes the root tool version VERSION_2`（重跑通过）
   → 现在卡在 `read materialized shared Skill resource: 404`。
   脚本期望路径 `.opencode/.session-skills/{root}/{digest}/references/guide.md`，
   而实现物化目录是 `session/skill-resource.ts` 的 `/home/sandbox/.local/share/opencode/session-skills`
    → **疑似脚本路径/摘要算法过时，原因尚未确认，不能排除产品缺陷**。确认方式：列出沙箱内实际物化目录对比。
8. **llm-stall T40.2.2（已通过）**：重跑 `sleep 15` + 排队消息，**27s 收敛**、`user=2 / assistant=2`、
   `long-done` 真实输出、末条回复含 `queued-behind`。此前 200s 超时属模型瞬时慢，非产品问题。

## 复跑要点

- 库必须与 Pod 一致（见发现 5）。
- 沙箱类脚本需 `OPENCODE_SANDBOX_ENABLED=1` + 本地 OpenSandbox 控制面 + `OPENCODE_SANDBOX_PROTOCOL=http`。
- `session-resources-owner` 用 `REPORT=<path>` 才能拿到被 `catch` 吞掉的失败详情；预算需 ≥10 分钟。
- `/generate` 请求体是 `{prompt: string}`，响应 `{data:{text}}`。

9. **context-insights 压缩采集 0/2（待查）**：`session-context-insights-v2.mjs` 在 sess-test（v2-test 库）跑，
   prompt 正常、CONTEXT_PROBE_SYSTEM_V2 已注入，但压缩后 kind=compaction 采集为 0 !== 2
   （/tmp/ctx2.log，证据 /tmp/ctx-ev3）。功能默认开启（非 off 即启用）。
   待查：mock 模型小 context 下 /compact 是否真实成功、压缩采集是否依赖压缩成功。
10. **read-peer-sandbox 3/3 通过**：B 沙箱造文件 → 跨会话读（懒复用不重建，sandbox 表 B 行数<=1）、
    fs/read 读 B 文件内容、A 沙箱卷隔离读不到 B 代码。注意 fs/read 路径相对 /workspace
    （传 src/index.ts，传 workspace/src/... 会 404）。

11. **anti-doom-loop 待核验**：有限源码搜索未定位到 `AntiLoop`，不足以证明机制不存在。
    探针中相同 `cat` 命令调用 5 次、工具均 completed、run succeeded（/tmp/adl2.log）。
    shell 非零退出不等于工具 error，不能用于验证 T42.2.1 的连续工具失败阻断。
    T42.4.1（3 次 shell completed）、T42.2.3（4 次调用完成）的探针通过；
    repeat 阻断、真正工具 error 的 fail-block 与 fatal 语义仍需确定性验证。
12. **T9.11 filesystem.changed 未见事件**：execd（shell API）写 /workspace 文件后 3 秒内
    无 `filesystem.changed`。core 源码 grep 无该事件发布点（仅 v1 残留），疑该事件在 V2 已移除或
    仅特定路径触发。尚需核验事件契约、触发路径与订阅范围，不能定性为产品缺陷。
13. **BTW-04 断言过严（测试问题）**：`/generate` 响应文本复述了命令内容（模型描述 echo 命令），
    纯文本 contains 断言误报"执行工具"；更准确的"assistant 无 tool part"断言未及验证。
    BTW-05 空历史未跑到（同一用例内断言顺序）。
14. **communication 部分探针结果**：joint-debug 4/4，仅客户端注入文本和空闲状态等断言，
    未验证执行中状态或 T21.5 跨沙箱真实 HTTP 联调；orchestrated 原脚本最终为 1/3（见发现17、19）。
15. **补齐批通过**：无模型 6/7（T39.1.2/2.1/4.1、T13.1+2、T13.11、T9.3 心跳；T9.11 见发现12）；

    轻量探针通过不能证明原场景失败由预算不足导致，也不能排除调度问题；原会话已清理，需保留证据后复现。
    客户端手动回传也不能替代真实子会话自动回传和 T23.4 联调通知。
20. **阶段性结论**：不提供缺少逐 ID 覆盖依据的规格通过总数。Java 未跑、BTW-05 未跑到、
